## src/server/login-page.js
- `BUG` src/server/login-page.js:63 (client script inside the template string; same hole in `safeNext` at :14-18) — open redirect after sign-in. The guard only rejects `next` whose 2nd char is `/` or `\`; `/login?next=/%09/evil.example` decodes to `"/\t/evil.example"`, passes, and `location.replace(next)` (line 74) resolves it through the URL parser, which strips tab/newline → `http://evil.example/`. Verified: `new URL("/\t/evil.com","http://box:4200/").href === "http://evil.com/"` and `safeNext("/\t/evil.com")` returns it unchanged (`j47-auth1.js`). A phishing link to the box's own login page therefore bounces the user to an attacker page right after a successful password entry. Fix: accept only `/^\/(?![\/\\])[^\x00-\x1f]*$/`, or compare `new URL(next, location.origin).origin === location.origin`.

## src/server/ws-server.js
- `BUG-HIGH` src/server/ws-server.js:283 (and :422 for the replication socket) — neither `wss.on('connection')` handler registers `ws.on('error')`. In `ws` 8.21 a receiver error (frame larger than `maxPayload` = 8 MiB by default, invalid UTF-8 in a text frame, bad opcode/RSV bits) is emitted as an `'error'` event on the WebSocket; with no listener EventEmitter throws, `process.on('uncaughtException')` (bootstrap/process-guards.js:21) logs and calls `process.exit(1)`. Failing case: any peer that can open `/api/ws` (no credential needed while `enforceAuth:false`, the shipped config; otherwise any authenticated client) sends one 9 MiB text frame, or one invalid-UTF-8 frame → the whole control server exits (systemd restarts it; Caspar keeps playing but WS clients, OSC mirror and in-memory state are lost). Verified: `j47-ws1.js` reproduces it with the identical listener set (`UNCAUGHT: Max payload size exceeded`). Fix: `ws.on('error', e => log(...))` in both handlers.
- `RISK` src/server/ws-server.js:180-188 — `queueStateChange` is a pure debounce: every new change calls `clearTimeout` + `setTimeout(75 ms)`, so a continuous stream of changes spaced < 75 ms never flushes (no max-wait). While that runs, `scene.live`, `channels.N`, `media` change frames are held back. Add a max-wait (flush when the oldest pending entry is > 250 ms old).
