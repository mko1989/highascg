## src/state/live-scene-reconcile.js
- `BUG` src/state/live-scene-reconcile.js:195,217 — `liveSceneState.clearChannel(ch)` returns a promise from `runSerialized` and is not awaited; `broadcastSceneLive(self)` at 217 runs synchronously after the loop and reads `getAll()` BEFORE the queued delete executes (`runSerialized` defers `fn` to a microtask, utils/async-serial-queue.js:15). - `BUG` src/state/live-scene-reconcile.js:38 — `pathsMatch` treats `a.includes(baseE) || e.includes(baseA)` as a match, a substring test on basenames: expected `media/loop.mp4` vs playing `media/bgloop.mp4` → true; `clip2` vs `clip` → true (`j47-state3.js`). So the connect-time reconcile (and playlist-path-match.js, playback-tracker reconcile, which import it) keeps a stale persisted live look / "now playing" row when Caspar plays a different clip whose name contains or is contained in the expected one. Use equality on the normalised basename, or a suffix match on a `/` boundary.
