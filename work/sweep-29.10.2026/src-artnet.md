## src/artnet/artnet-packet.js
- `BUG` src/artnet/artnet-packet.js:17 — the ArtDmx Length field is read little-endian (`msg.readUInt16LE(16)`); Art-Net defines it big-endian (hi byte first), and `src/fixtures/artdmx.js:42` correctly uses `readUInt16BE`. The wrong value is only masked when the length is 512 (0x0200 read LE = 2) or a multiple that happens to stay below the packet size. For any other length the LE value is huge, `payloadLen = min(512, max(huge, …))` becomes 512, and the loop reads past the end of the packet. Run on built packets (valid ArtDmx, length field in network order): length 512 → 512 slots; 256 → 256; **18, 24, 100 and 2 → `ERR_OUT_OF_RANGE` thrown**. Failing case: a source that sends a trimmed universe (e.g. 24 channels) never drives the border; every packet throws, is caught in `artnet-udp.js:105-109`, and logs `Message handler error` PLUS the stack at error level per packet (44 lines/s of journal spam). Fix: use `readUInt16BE(16)`, cap by `msg.length - 18`, and return `data` as the subarray.
- `QUALITY` src/artnet/artnet-packet.js:9-19 — second ArtDmx decoder. `src/fixtures/artdmx.js:39 decodeArtDmx` already parses ArtDmx correctly (BE length, 15-bit port address, `subarray` that cannot over-read) and the DMX viewer uses it. The lighting input should use the same one; the divergence is exactly how the bug above survived. Also `data` is built with a per-byte `push` loop into a JS array.
- `OK` for the port address: `(subuni << 8) | net` matches `applyPatch` (`artnet-runtime.js:16-17`), so there is no off-by-one between the packet and the stored key; universe is 0-based in both.

## src/artnet/sacn-receiver.js
- `BUG` src/artnet/sacn-receiver.js:80-88 — received levels are scaled wrongly. `sacn` 4.6.2's `Packet.payload` getter (`node_modules/sacn/dist/util.js:13-20`) returns **percent** (`val / 2.55`, 0–100, zero channels omitted) unless the packet was built with `useRawDmxValues`, and the `Receiver` has no raw option (README Table 1). The code stores `Math.round(val)` clamped to 255, as if the values were 0–255. Failing case: a desk sends DMX 255 on the opacity channel → the receiver gets 100 → border opacity 100/255 = 0.39; DMX 128 → 50 → 0.20; colour channels top out at 0x64. Worse, the enable channel: `dmxEnabledSticky` turns the border off for any value below 128-10 = 118 and the scaled value never exceeds 100, so every sACN frame with the enable channel mapped yields `enabled=false` — the border is switched OFF whatever the desk sends. The type bands (64/128/192) are likewise reached at 2.55× the DMX value. Not covered by a test (WO-179 A179.1 hardware check was never ticked). Fix: `Math.round(val * 2.55)` (better, read `packet.payloadAsBuffer` when present, which is already raw bytes).
- `BUG` src/artnet/sacn-receiver.js:45-50 — the universe is fixed when the receiver is created. `_ensureListening` returns when `this._socket` exists, and `new Receiver({ universes: [this._inputUniverse] })` joins only that multicast group. Failing case: universe 1 → 2: packets for 1 are dropped as `wrongUniverse`, packets for 2 are never delivered; input dead until restart or protocol swap. Same for a port change. Fix: on `reconfigure`, `removeUniverse(old)` / `addUniverse(new)` (both exist in `receiver.js:54-66`) or close and recreate.
