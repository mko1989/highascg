## src/replication/sync-project-media-rsync.js
- `RISK` src/replication/sync-project-media-rsync.js:117,124 — containment is tested with `abs.startsWith(mediaBase)` / `src.startsWith(REPO_ROOT)`: a prefix test without a separator. `resolveMediaFile` (sync-project-media.js:18) joins an arbitrary project ref onto `mediaBase`, so a ref like `../media-old/x.mp4` resolves to `<root>/media-old/x.mp4`, passes the check when a sibling directory shares the prefix, and becomes the rsync path `media/../media-old/x.mp4` (the receiving wrapper rejects `..`, so it fails there, but the local plan and the "linked media" counts are wrong). Fix: `if (runtime?.lastMediaSync?.inProgress) return { ok:false, error:'media sync already running' }`.
- `RISK` src/replication/sync-project-media-rsync.js:94-142 `buildProjectMediaRsyncPlan` — every path in the plan is derived from files that exist on THIS box (`resolveMediaFile`, `resolveTemplateFile`, `buildProjectMediaManifest` all stat the local disk). Fix: for `pull`, plan from the leader's manifest (`fetchPeerProjectMediaManifest`) instead of the local disk.
