## client/components/timeline-transport.js
- `BUG` client/components/timeline-transport.js:375-395,90-100 — the current-time field commits via `parseTcInput` then `doSeek(ms)` with no range clamp. Typing `99:00:00:00` (or `-1:00:00`) sets `playback.position` to 356400000 / -60000 ms client-side and the field is re-rendered from it, while the server clamps its own position (`eng.seek`, src/engine/timeline-playback-runtime.js:205-209). Root cause is in timeline-canvas-utils.js `parseTcInput` (see part 8); fix either side by clamping `ms` to `[0, tl.duration]` in `onCurCommit`.
- `RISK` client/components/timeline-transport.js:60-69,111-141 — `syncToServer` swallows both failures (`PUT` then `POST` fallback, both `catch {}`), so `togglePlay` proceeds to `seek`/`sendto`/`play` against a stale or missing server-side timeline without telling the operator; `await syncToServer(tl)` can never fail. Same for the Take button (349-373: `.catch(() => {})` on `/take`, then it still flips `view.sendTo.program = true` locally) and Pause (115-120: UI flips to paused before the request, error ignored). An on-air Take or Pause that fails is invisible to the operator. Fix: let `syncToServer` return/throw a status and toast on failure.
- `QUALITY` client/components/timeline-transport.js:174-176 — timeline `t.name` and `t.id` are interpolated into `<option>` HTML unescaped (also `lab`, `tw` on 230-238). A timeline name containing `<`/`"` (rename prompt, or a project imported from another node) breaks the selector or injects markup. Use `escapeHtml`/`escapeAttr` (client/lib/dom-escape.js).
- `QUALITY` client/components/timeline-transport.js:390-394 — pressing Enter in a time field calls `blur()`, which fires both `change` and `blur`, so `onCurCommit` runs twice (two `/seek` posts). The doc comment for `createTimelineTransport` (lines 15-30) is also attached to `tlIcon` (line 31-32) instead of the function.

## client/components/variables-panel.js
- `BUG` client/components/variables-panel.js:85-88 — the copy button calls `navigator.clipboard.writeText(key)` with no guard or fallback. `navigator.clipboard` is `undefined` outside a secure context, i.e. whenever the UI is opened over plain `http://<box-ip>:4200` from another machine (the HTTPS proxy is deprecated); the click handler then throws a TypeError before the "Copied!" state is set, so nothing is copied and nothing is shown. The kiosk on localhost works. client/components/logs-modal.js:414-421 has the correct try/catch + `document.execCommand('copy')` fallback. A rejected `writeText` promise is also unhandled here.
- `BUG` client/components/variables-panel.js:114,118 — the `store.subscribe(...)` is released only via `container.onUnmount`, which nothing ever calls (grep: `rg -n "onUnmount" client --glob '!map-data.json'` → only this assignment; settings-modal.js:264 just calls `mountVariablesPanel(varPane)` each time the modal opens). The store is a process-wide singleton (`getVariableStore`), so each Settings open adds one more subscriber that re-renders a detached table on every `variable_update`/`state`. Failing case: open and close Settings 20 times → 20 full `render()` passes (sort of all variable keys + rebuild tbody) per variable update. Fix: unsubscribe when the pane is removed (MutationObserver like timer-control-panel.js:370-377, or have settings-modal call an unmount hook).
- `QUALITY` client/components/variables-panel.js:62-83 — every update rebuilds the whole table (all variables, string-concatenated `innerHTML`) with no throttling; OSC-driven variables update continuously, which also resets text selection and the 1 s "Copied!" state of the copy buttons. Coalesce with `requestAnimationFrame`.
