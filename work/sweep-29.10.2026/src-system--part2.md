## src/system/video-feed-encoder.js
- `RISK` src/system/video-feed-encoder.js:130 (and video-feed.js:89-91) — the ffmpeg `ChildProcess` has no `'error'` listener. Verified with a mock (`j48-enc.js`): `proc.emit('error', ENOENT)` throws "spawn ffmpeg ENOENT" out of the emitter. In the worker thread that kills the worker; video-feed.js only listens for `'error'`, never `'exit'`, and keeps the dead handle in `worker`, so `sync()` keeps `postMessage`-ing to a dead thread and a fresh worker is only created after EVERY client has left (`wanted.size === 0` branch). Result: the remote video feed is permanently dark for connected clients after one ffmpeg spawn failure (missing binary, EMFILE). Fix: `p.on('error', …)` that calls `kill()`, and `worker.on('exit', () => { worker = null; })` in video-feed.js.
- `RISK` src/system/video-feed-encoder.js:150-167 — `inflight` is only decremented when ffmpeg emits a JPEG or exits. A wedged ffmpeg (input accepted, nothing out; the comment at :34 describes one such mode) leaves `inflight > 0` and the encoder idles forever with no watchdog. Add a timeout that `kill()`s after ~2 s without output.

- `BUG-HIGH` src/system/video-feed.js:131 — `new URL(req.url || '', 'http://127.0.0.1')` runs for EVERY `'upgrade'` request, before the origin and auth checks (:134-141) and with no try/catch. - `BUG` src/system/video-feed.js:102-113 — the per-client `ws` has no `'error'` listener and the message handler dereferences `m.roles` without checking `m`.
