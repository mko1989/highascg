## src/sampling/dmx-output.js
- `BUG` src/sampling/dmx-output.js:77-80 — `new sacn.Sender({ universe, destination })`: the sacn 4.x option is `useUnicastDestination` (node_modules/sacn/src/sender.ts:~50,95); `destination` is ignored, so a fixture with `protocol:'sacn', destination:'192.168.1.50'` is always sent to the multicast group. Ran with the real `sacn` and a stubbed socket: packet 1 went to `239.255.0.1`, configured `192.168.1.50`.
- `BUG` src/sampling/dmx-output.js:84-90 — sacn scales payload values by 2.55 unless `useRawDmxValues` is set (sacn/src/packet.ts:182-188: `inRange(payload * 2.55)`), but the sampler passes 0-255 values. Ran: values `[200,100,50]` went out as `255,255,127`; anything >= 100 is full. Fix: `defaultPacketOptions: { useRawDmxValues: true }` on the sender.
- `BUG` src/sampling/dmx-output.js:72-91 — one sACN sender per `universe:destination`, but every `send()` posts a packet that contains only THIS fixture's slots (a sACN packet always carries all 512, unlisted ones are 0). Two fixtures in one universe overwrite each other: ran fixture A at ch1-3 then fixture B at ch10: packet 2 had ch1-3 = `0,0,0`. (Art-Net does not have this problem because dmxnet keeps the universe buffer.) Fix: keep a 512-byte buffer per sender and send the merged universe.
- `BUG` src/sampling/dmx-output.js:93-102 `stop()` — only clears the two Maps. dmxnet senders own a socket and a `setInterval(transmit, 1000)` (node_modules/dmxnet/lib.js:377-396) that keeps re-sending the last frame until `sender.stop()` is called; sacn senders own a UDP socket (`close()` exists). Ran with a fake dmxnet: after `stop()` `sender.stop()` was never called (sacn sockets closed: 0). So after `settings.dmx.enabled` is switched off, or on any `stop()` before a restart (`_updateConfigImpl`), the old Art-Net senders keep broadcasting the last colours every second forever and a new set is created on top at the next start (leak, and the lights cannot go dark). Fix: call `sender.stop()` / `sender.close()` for every entry (the empty `for` loop at 94-96 shows the intent) and null `this.artnet`.
- `RISK` src/sampling/dmx-output.js:3,16,52,68 — known (WO-807 §Investigation, WO-615 §160, and `src/fixtures/artdmx.js:5-6`): `new dmxnet.dmxnet()` binds a listener on UDP :6454 (the box's own lighting input), the default destination is 255.255.255.255, `setChannel` sends one datagram per channel (a 3-channel fixture = 3 packets per frame; dmxnet's `transmit` callback also `throw`s inside the UDP callback, lib.js:424), and the universe is clamped to 0-15 (line 30) so universe 16+ lands on 15. Not touched while the sampler stays deprecated; do not re-enable it without replacing this file with the `artdmx.js` sender.
- `RISK` src/sampling/dmx-output.js:90 — `sender.send()` of sacn returns a Promise that rejects on socket errors (ENETUNREACH when the link drops); it is neither awaited nor caught → unhandled rejection per frame (process-guards logs them, 25 log lines per second).
- `QUALITY` src/sampling/dmx-output.js:31-34 — the sACN cache key uses the raw `universe` (`'1'` and `1` make two senders and two sockets); `startChannel` is clamped silently to 1-512.

## src/sampling/dmx-sampling-ingress.js
- `RISK` src/sampling/dmx-sampling-ingress.js:172-176 (+ dmx-sampling.js:258-279) — if the local ffmpeg dies or Caspar restarts (the `ADD … STREAM` consumer disappears with it), nothing restarts it: the `exit` handler only logs, `udpFfmpegProc` is not cleared, and `updateConfig` does not re-run `start()` because the plan, channel set and ingress mode are unchanged (`_analyzeConfig`, dmx-sampling.js:148-158), even though index.js:257/381, periodic-sync.js:361 and fetch-server-info-config.js:50 call it on every config reload / Caspar connect. The 5 s watchdog (78-90) warns only before the first byte. After that DMX output freezes on the last colours with no warning.
- `RISK` src/sampling/dmx-sampling.js:218 + ingress.js:195-217 (FILE mode, off by default) — `fs.createReadStream(fifoPath)` opens a FIFO read-only; `open()` blocks in the libuv thread pool until a writer connects. With the "FILE→FIFO never writes" Caspar builds named in the comment at line 31, one pool thread per channel stays blocked forever (the pool has 4), starving `fs`/`dns`/`crypto` calls for the whole process; `readStream.destroy()` cannot unblock it. The FIFOs live in the repo root (`.sampling.N.pipe`) and are in neither `.gitignore` nor `.stignore` (`git check-ignore -v` → not ignored).
- `QUALITY` src/sampling/dmx-sampling-ingress.js:209 — `execSync(\`mkfifo "${fifoPath}"\`)` through a shell; use `execFileSync('mkfifo', [fifoPath])`.
- `QUALITY` src/sampling/dmx-sampling-ingress.js:100-108,129 — the stream URI match uses `u.includes(\`:${port}\`)`, which also matches a longer port that starts with the same digits.
- `QUALITY` src/sampling/dmx-sampling-ingress.js:268 — `DMX_UDP_PORT_OFFSET` is exported but never imported (used only inside this file).

## src/sampling/dmx-sampling.js
- `BUG` src/sampling/dmx-sampling.js:121-124 — `_analyzeConfig` returns `needsRestart: false` when the fixture list is empty, so removing the last fixture of a running config does not stop anything: the ffmpeg readers and the Caspar STREAM/FILE consumers stay up (the only effect is `_processFrame` dropping every frame at 311). Ran (j46-sampling.js): enabled with one fixture → `stop | start [1]`; then `fixtures: []` → no stop/start call, `channels` still has channel 1. They stop only when `enabled` goes false. Fix: treat "had channels, now none" as a restart.
- `BUG` src/sampling/dmx-sampling.js:145-158 — a changed `fps` is not part of `needsRestart` (only plan, channel set, ingress mode). `this.fps` is updated (145) but the ffmpeg args and the Caspar consumer were built at `start()` with the old value (`-r`, `buildFfmpegArgs`), so the setting has no effect until some other change forces a restart. Ran: fps 25 → 50 → no stop/start, `m.fps` becomes 50.
- `RISK` src/sampling/dmx-sampling.js:299-301 — a worker `error` is only logged; the dead worker is never replaced, and `_processFrame` keeps posting to it. With the worker crash in sampling-worker.js (BUG below) one malformed fixture silences sampling until the next restart.
- `RISK` src/sampling/dmx-sampling.js:328-370 — results are sent to `dmx:colors` over the WebSocket at the sampling rate (25-60 messages/s to all clients) even when no UI is showing the live preview.
- `DEAD` src/sampling/dmx-sampling.js:26-28,140-142 `this.width`, `this.height`, `this.currentScale` — assigned in `_analyzeConfig` from the first planned channel and never read. grep `currentScale` over src client tools index.js → only these lines; `.width/.height` of the manager are not read by anything (the per-channel `plan.fullW/fullH` is used).
- `QUALITY` src/sampling/dmx-sampling.js:304-326 — `_processFrame` posts a Buffer view with `postMessage`; structured clone copies the whole underlying ArrayBuffer (the concatenated chunk buffer, up to several frames), not just the `frameSize` view, and there is no back-pressure (the comment at 313 says so deliberately).

## src/sampling/sampling-worker.js
- `BUG` src/sampling/sampling-worker.js:70 — `if (gamma) updateGammaTable(gamma)` mutates one module-level table; a fixture without `gamma` uses whatever the previous fixture (or message) left behind instead of the 2.2 default. Ran (j46-worker.js, 4x4 grey 128 frame): fixture B alone → `56,56,56`; message with A (gamma 1.0) then B (no gamma) → A and B both `128`; the next message with B alone still gives `128` (the table stays at 1.0 until some fixture sets 2.2 again). Fix: `updateGammaTable(gamma || 2.2)` per fixture.
- `BUG` src/sampling/sampling-worker.js:148-150 — `avgR *= (brightness || 1.0)` makes `brightness: 0` full brightness. Ran: `brightness: 0` → `128,128,128`. A per-fixture blackout is impossible; use `brightness ?? 1`.
- `BUG` src/sampling/sampling-worker.js:68,72,77-78 — `sample.x` and `grid.cols` are read without a guard, and a throw inside the `parentPort.on('message')` handler terminates the worker thread. Ran: a fixture without `grid` → `TypeError: Cannot read properties of undefined (reading 'cols')`. `_planChannels` (dmx-sampling.js:72) treats `grid` as optional, so the two sides disagree; the manager only logs the worker error (dmx-sampling.js:299) and never restarts it. Fix: default `grid = { cols: 1, rows: 1 }`, `sample = {}`, and wrap each fixture in try/catch.
- `QUALITY` src/sampling/sampling-worker.js:32-33 — `amber` is computed for every call even for plain RGB formats; `extractColors` rounds nothing (floats like `amber = min(r,g)*0.5` reach `DmxOutput`, which rounds).
