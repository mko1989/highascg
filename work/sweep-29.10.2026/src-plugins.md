## src/plugins/plugin-manager.js
- `BUG-HIGH` src/plugins/plugin-manager.js:123-165, :186-196 (called from api/routes-plugins.js:55-70) — path traversal into `require`. `validatePluginInput` (the only id/moduleName validation) runs for `add` and for `update`'s optional `moduleName`, but `POST /api/plugins/:id/enable|disable|update` take `id` straight from the URL (`decodeURIComponent(m[1])`, routes-plugins.js:55-56) and call `setEntry(ctx.config, id, …)` without checking it against `isValidPluginId`. `listPlugins` then synthesizes a plugin whose `moduleName` defaults to the id (:150), and `enablePluginNow` -> `moduleRegistry.tryLoad(moduleName)` does `require('./' + name + '/register')` relative to `src/`. Reproduced: with id = `../../../../tmp/.../t3/evil` (a directory holding `register.js`, URL-encoded as `..%2F..%2F...`), `enablePluginNow` executed that file (`REGISTER.JS EXECUTED`, `[modules] loaded ...`). It is persisted: `persistPlugins` writes the entry to config (enabled by default, :152), so `loadEnabledPlugins` (:174-184) `require`s it again at EVERY boot, and `moduleName` read back from config is never re-validated. Needs a `register.js` on disk at the target path and an API token, so it is not an anonymous RCE, but it turns write access to any directory plus the API into code execution inside the playout process, and a bad id pollutes the persisted config. Fix: validate `id` and `moduleName` with the existing regexes in `listPlugins`/`loadEnabledPlugins`/`enablePluginNow` and in the three route actions (reject, do not create the entry); make `tryLoad` refuse names containing `/`, `\` or `..`.
- `BUG` src/plugins/plugin-manager.js:84-96 — `validatePluginInput(…, 'update')` always sets `out.version`, `out.repoUrl`, `out.pinnedRef` to `''` when the fields are absent from the payload, and the route spreads the result into `setEntry`. `POST /api/plugins/x/update {"pinnedRef":"v2"}` therefore wipes the stored `version` and `repoUrl`. Only copy fields that were actually sent.
- `BUG` src/plugins/plugin-manager.js:198-210 — `disablePluginNow` returns `ok: shutdownOk && unloaded`; `moduleRegistry.shutdownOne` returns `false` for a module that is not loaded, so disabling a plugin that is already not loaded (e.g. disabled at boot, or a failed load) answers 409 `disable_failed` although the entry was correctly marked disabled. Failing case: disable a plugin whose module failed to load -> 409.
- `QUALITY` src/plugins/plugin-manager.js:128-146 — a bundled catalog plugin with `enabled: true` but a failed load is reported `status: 'error'`, while a non-catalog one is `not-installed`; the two lists use different semantics for the same condition.
- `DEAD` src/plugins/plugin-manager.js:215 `normalizeStore` export — used only inside this file. grep -rlw `normalizeStore` over src tools client godot scripts index.js -> none other. (`getKnownPluginIds` is test-only: tools/smoke/smoke-wo265-cg-studio-tab.test.js.)
