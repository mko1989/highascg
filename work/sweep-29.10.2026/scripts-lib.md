## scripts/lib/decklink-install-lib.sh
- `BUG` scripts/lib/decklink-install-lib.sh:213-234 — `decklink_install_vendor_pair` is always called as `if decklink_install_vendor_pair …; then log "ok: installed"` (scripts/runtime/decklink-install-from-exfat.sh:84), and bash disables `set -e` for the whole function body in that context. Failing case: a `.deb` pair whose second `dpkg -i` still fails after `apt-get install -f` (L216/L221) → the failure is ignored, the function falls through to `modprobe`/`return 0` (L234) → the service logs "ok: installed Desktop Video X" and exits 0; the `ERROR: dpkg install failed` branch (runtime script L90) is unreachable for dpkg failures. Reproduced: `bash -c 'set -e; f(){ false || { false; false; }; echo after; return 0; }; if f; then echo ok; fi'` prints `after` and `ok`. Fix: `|| return 1` after the retry `dpkg -i`.
- `BUG` scripts/lib/decklink-install-lib.sh:82,144-176,233 — leaked extraction directories. With only a `Blackmagic_Desktop_Video_Linux_*.tar.gz` in `vendor/decklink`, `~/Downloads` or the stick (the real vendor layout, WO-428), `decklink_find_newest_vendor_pair` extracts the debs into a fresh `mktemp -d` each call. `decklink-install-from-exfat.sh` calls it twice (via `decklink_needs_install_from_vendor` L60, then directly L65), so the first directory is lost (`DECKLINK_EXTRACT_TMPDIR` is overwritten at L83), and every `skip:` / `--dry-run` exit (L62, L67, L81) never removes the second. Cleanup exists only on the success path (L233). The unit runs every boot (`highascg-decklink-install.service`, `--boot`, `Before=casparcg-server`), so on a live ISO (tmpfs /tmp) each boot leaves tens of MB in RAM and pays two gunzip passes before Caspar starts. Also `break 2` (L172) stops after the first archive even if it held no `desktopvideo_*.deb`. Fix: trap-clean `DECKLINK_EXTRACT_TMPDIR` in the caller, extract once.
- `BUG` scripts/lib/decklink-install-lib.sh:134,164 — documented priority order (L58-61: GUI-upload dir, Downloads, exFAT, bridge) is inverted on ties: `sort -V | tail -1 == "$ver"` is also true when `ver == best_ver`, so a later directory replaces the earlier pair, including `best_gui`. Failing case: `vendor/decklink` has `desktopvideo_16.4_amd64.deb` + `desktopvideo-gui_16.4_amd64.deb`, the stick has only the main `.deb` of the same version → `best_gui` becomes `""` and the GUI package is not installed. Fix: use `-gt` semantics (strictly newer) when comparing.
