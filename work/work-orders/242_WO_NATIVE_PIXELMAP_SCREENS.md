# WO-242 — Native pixel-map screens: dedicated channel + improved-artnet consumer per fixture array; JS pixel-mapping deprecated

**Status:** Implemented (T242.1-T242.7 done; A242.1 is an owner action, unchecked) | **Priority:** High | **Date:** 2026-07-15
**Source:** owner: "i dont want the js pixelmapping. i want to use native artnet consumer from the improved v. and as an addition be able to create the pixel mapping 'screen'/channel that would then send artnet to arrey of fixtures."

## Design
- **New screen-destination type `pixelmap`** in the screens/device config: allocates a dedicated Caspar channel; operator sets: video-mode (standard small mode or custom WxH if the 2.6-dev config supports custom modes — verify in src-tree), fixture array (rows × cols, start-universe, start-address, color order RGB/RGBW, orientation/serpentine if the consumer schema supports it — use ONLY schema elements documented in docs/WALKTHROUGH_ARTNET_LED_WALL.md with their artnet_consumer.cpp cites), destination IP/broadcast + refresh rate per schema.
- **Config generator emits the channel + `<artnet>` consumer block** (closing the WO-241-flagged gap: generated, not hand-edited — survives regen). Standard caspar-restart-dirty affordance.
- **Looks integration for free:** the pixelmap channel registers as a PGM-ONLY screen destination (WO-160b pipeline) — it appears in decks/screen selectors (respecting WO-222 screen labels), content is authored/taken exactly like any screen; compose preview optional later.
- **JS pixel-mapping deprecated:** hide the pixel-map editor tab + JS artnet/sacn output UI behind a settings flag `legacyJsPixelmap` default OFF (code stays, nothing deleted). HONEST consequence in the WO + docs: sACN output and live (restart-free) remapping go away with it — native is Art-Net + config+restart only.
- **Docs:** update docs/ARTNET_PIXEL_MAPPING.md + walkthroughs: JS engine badged [DEPRECATED - legacy flag], new "Pixel-map screen" flow becomes the primary walkthrough.
