## 1. Review findings (2026-07-13)

### How configs are created/managed

- **casparcg.config** is generated programmatically (JS template strings): `buildConfigXml` in `src/config/config-generator.js:35-117` + channel/audio/OSC sub-builders (`config-generator-channels.js`, `config-generator-audio-xml.js:310-330`, `config-generator-osc-xml.js`), fed by `buildCasparGeneratorFlatConfig` (`src/config/build-caspar-generator-config.js`). Written by `writeCasparConfigToDisk` (`src/api/routes-caspar-config.js:73-134`; path resolution :54-61 — saved `casparServer.configPath` → `CASPAR_CONFIG_PATH` env → `config/casparcg.config`). Rewritten on caspar-config apply (:252), full-config apply (`src/utils/full-config-apply.js:74`), host-live-source repair (`src/config/host-live-sources-setup.js:61`), and replication follower regeneration (`src/replication/follower-machine-profile.js:191-204`, `follower-caspar-output.js:252`).
- **`casparServer.casparConfigOverride`** bypasses the generator entirely — raw stored XML written verbatim, generator DeckLink/keyer fixes skipped (`routes-caspar-config.js:94-104`).
- **App config** is the modular `config/` directory via `ConfigManager` (`index.js:71-75`, `config-manager.js:199-241`, `MODULAR_KEYS` :31-53) — NOT the root `highascg.config.json`.

### Deprecated values verdict

The generated casparcg.config is **not full of deprecated stock values** — genuinely deprecated 2.x elements (channel-grid, flash, legacy thumbnails/mixer forms, auto-deinterlace, pipeline, legacy paths) are all absent. What it does contain are **custom-build extensions** for the bundled CasparCG 2.5 fork with PRs #1718–#1720 (`docs/ISO_CONTENTS.md:29,130`, WO-07): top-level `<system-audio>` (L10-12), `<portaudio>` block (L13-21), `<sbs-key>`/`<high-bitdepth>`/screen `colour-space` (PR #1718), DeckLink `<color-space>` (L71). One element is unconfirmed even for the fork: `<mixer><audio-osc>` per channel (emitted at `config-generator-channels.js:174`) — not a stock mixer child; verify the build consumes it. **Portability risk:** pointed at a *stock* 2.5, these extensions are silently ignored → audio routing assumptions break.

### Lifecycle hazards found

1. **XML write is NOT atomic** — `routes-caspar-config.js:107-108` does a direct `fs.writeFile`; crash/concurrent write can truncate `casparcg.config` → Caspar fails to parse on next start. (JSON path IS atomic: tmp+rename, `config-manager.js:153-155,271-276`.)
2. **Stale root `highascg.config.json`** (May 21) is never loaded in this deployment yet sits in the repo root diverged from live config (`screen_count: 1` vs live `2`); contains the confirmed-deprecated `mediaMount` block (:169-172) that `_stripLegacyMediaMount` (`config-manager.js:282-304`) exists to remove. Edit-the-wrong-file footgun.
3. **`.bak.<epoch>` backups: manual, unbounded** — no app code writes them; origin is a documented manual `cp` (`scripts/setup/MANUAL_INSTALL.md:391`). 9 files accumulated in `config/` (plus `casparcg.config.iso`, `casparcg copy.config`), no rotation, and they ride along the exFAT config sync (`tools/eggs/live-usb/EXFAT_DATA_ZERO_TOUCH.md:120`).
4. **No write serialization** — overlapping `ConfigManager.save()` calls (UI save vs full-apply's save at `routes-caspar-config.js:123`) are last-writer-wins; the 300 ms dedupe (:160-171) only suppresses events.
5. **Migrations are ad-hoc, unversioned** — no `configVersion`; migrations (`migrateUiNuclearPassword` :119-127, `migrateHostLiveSourcesConfig`, mediaMount strip) re-detect on every load and can't be retired.
6. No schema validation on JSON load (`JSON.parse` + shallow merge, unknown keys silently kept). Spot-check found **no dead live keys** (all sampled keys are read by src/) — the dead keys live only in the stale root file.
7. `webui-port.json` (port 4350) is not read by src/ — tooling-only, out-of-band from ConfigManager; document or fold in.
