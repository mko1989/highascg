# WO-645 — Start-up: boot to the desktop with "Start operator here / Run headless"; autostart is an opt-in

Owner, 21.10: *"i think the current autostart of caspar and everything is not the way to go. this should stay as an
optin in settings to autostart casparcg with or without gui etc. and for normal operation start into desktop on each
screen a small window with start operator here, or run headless."*

Successor of [WO-609](./609_WO_godot_cutover_packaging_kiosk_decommission.md) T2 (the GUI autostart) for the start
policy; builds on [WO-638](./638_WO_boot_monitor_assignment.md) (the per-screen boot prompt and the Caspar gate).

## Investigation

The boot chain today (subagent map, re-checked by hand where it matters):

1. nodm autologin (`/etc/default/nodm`, `NODM_USER=casparcg`) → `~/.xsession` → Openbox → `~/.config/openbox/autostart`
   (generated by `scripts/setup/09-openbox-autostart.sh`). It lays out X, then starts the Godot client after 8 s.
   There is no Openbox menu of our own (`~/.config/openbox/menu.xml` missing), so a closed client could only be
   started again from a terminal.
2. `highascg.service` (node, `Restart=always`) starts the WO-638 gate at `index.js:355` (`startBootScreenGate`).
3. `casparcg-server.service` → `run.sh`. The first launch of a boot waits for `~/.highascg/run/caspar-screens-ready`
   to hold the boot id, but only up to `CASPAR_SCREEN_GATE_SEC` (240 s), then starts anyway (`run.sh:168-182`).
4. WO-638's question was asked only with 2+ lit screens, counted down from 120 s, and node took the default after 200 s.
   So Caspar always came up by itself within about 4 minutes. Nothing in Settings could change any of it:
   `operatorTools.bootScreenPicker` had no UI, and there was no autostart flag at all (`config/*.json`, `src/config`).

## What was done

- **`startup.mode`** (`src/config/defaults-core.js`, default `ask`; `src/system/boot-screen-assignment.js`):
  - `ask`: every boot, also with one screen, the launcher shows on every screen. Node writes
    `~/.highascg/run/caspar-screens-hold` (this boot's id) and starts no fallback timer. Nothing starts until a person
    answers.
  - `gui`: autostart CasparCG and the operator GUI, the WO-638 behaviour (multi-screen question, 120 s, default).
  - `headless`: autostart CasparCG with no question. The client the session autostart started quits.
  - Unknown values read as `ask`.
- `bootStatus` carries `mode`, `launcher`, and `headless` (this boot runs headless: the mode, or "Run headless" was
  answered). `resolve(…, {how: 'headless'})` settles on the default operator jack, so a GUI started later lands
  there. It records `how: 'headless'` and releases Caspar. With no lit screen at all it still releases Caspar.
- **`run.sh`**: the backstop does not apply while the hold file holds this boot's id. The released/timed-out log line
  now checks the gate file itself.
- **Settings**: `startup` is in the GET (`settings-get.js`) and the hand-listed POST (`settings-post.js`, both the
  merge and `newConfig`, see the WO-619 lesson). Godot Settings → Defaults → **Start-up**, "When the box starts":
  Ask on every screen / Start CasparCG and the operator GUI / Start CasparCG headless.
- **Godot client**:
  - `app/boot_question.gd` (new, moved out of `main.gd`, which was at 500 lines).
    - With the launcher up, the main window is minimized. Godot refuses to hide its main window (`Can't change
      visibility of main window`, probed); minimize / restore works under Openbox (probed: `WM_STATE Iconic` → `Normal`).
    - Start operator here → the window comes back on that screen. Run headless → the client quits.
    - `--autostart` and a headless boot → quit at once (`operator_screen_model.gd autostart_quits`).
  - `app/operator_screen_picker.gd`: launcher mode, two buttons per screen ("Start operator here", "Run headless"),
    no countdown, no Esc / close, the note "CasparCG starts when you choose."
- **Openbox** (`09-openbox-autostart.sh` and this box):
  - The autostart passes `--autostart`.
  - New `~/.config/openbox/menu.xml`: right-click the desktop → **Operator GUI** (started by hand: always runs),
    Terminal, Reconfigure.
- Not done: the web settings modal has no Start-up control yet (Godot only). `display-mode x11-only` is untouched,
  and its xterm text ("CasparCG not started") is still stale (Caspar starts in that mode too, subagent finding).
