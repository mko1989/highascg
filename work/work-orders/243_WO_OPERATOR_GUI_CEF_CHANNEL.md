# WO-243 — Operator GUI channel: CEF web-UI layer over routed preview channels, own screen consumer

**Status:** Implemented (T243.1-T243.4 done; A243.1 is an owner action, unchecked) | **Priority:** HIGH (owner-picked architecture)
**Owner check:** A243.1

## Owner intent (verbatim)
"id like to keep the current multiviewer but add the operator gui screen consumer with cef displaying the webui and overlayed routed channels."

## Architecture
The multiview channel/consumer is UNTOUCHED. A new dedicated Caspar channel ("operator GUI channel"):
- **Route layers (10..49)**: `route://<pgm/prv channel>` sources, one per GUI preview box, positioned with `MIXER FILL` to match the DOM rect of that preview box (normalized 0-1 coords — FILL takes fractions).
- **Top CEF layer (100)**: html producer playing the web UI (`http://127.0.0.1:4200/?cefOperator=1`). The UI in this mode renders TRANSPARENT rectangles where compose previews normally draw, so the route layers below show through. CEF composits transparency natively in Caspar — no OS compositor involved.
- **Screen consumer** on the operator monitor (borderless, positioned like other screen consumers).
- Input: the EXISTING raw-CDP interactive bridge (WO-247) — the GUI page becomes a focusable CEF target; X11 capture on the operator display forwards mouse/keys.

## Tasks

**T243.1 — destination type `operator_gui`** (`src/config/screen-destinations.js` + device-view UI form/actions mirroring WO-242's pixelmap additions)
Model: `{ id, label, mode:'operator_gui', physicalPort (optional — default resolved operator monitor), width, height, fps, guiUrl (default 'http://127.0.0.1:4200/?cefOperator=1') }`. Generator emits: channel (video mode from width/height/fps like other screens) + `<screen>` consumer (borderless, windowed per existing screen-consumer conventions, positioned at the chosen monitor's layout rect). NOT registered as a takeable PGM screen (exclude from programChannels — follow the multiview exclusion in routing-map.js). At most ONE operator_gui destination (validate in CRUD).

**T243.2 — server runtime orchestrator** (`src/system/operator-gui-channel.js`, new)
- On Caspar connect/startup (hook where multiview re-apply happens): if an operator_gui channel exists, `PLAY <ch>-100 [HTML] "<guiUrl>"` (re-ADD after Caspar restart, like the CG orphan sweep does for templates).
- `POST /api/operator-gui/layout` — body `{ cells: [{ id, role:'pgm'|'prv', mainIndex, rect:{x,y,w,h} }] }` with rect in viewport fractions (0-1). For each cell resolve the source channel from the channel map (`programChannels[mainIndex]` / `previewChannels[mainIndex]`; skip cells whose channel is null) and emit `PLAY <ch>-<10+i> route://<src>` (only when changed) + `MIXER <ch>-<10+i> FILL x y w h` (one decimal-normalized line, mirror multiview-apply's line building). Layers beyond the current cell count get `STOP`+`MIXER CLEAR`. Debounce 150ms server-side; serialize via the existing AMCP queue conventions.
- `DELETE /api/operator-gui/layout` clears route layers (GUI layer stays).
- REGISTER both routes in `src/api/router.js` (repeat offender — verify with a grep assertion in the smoke).
- Register the channel as an interactive zone (id 'operator_gui') in cef-interactive-bridge-zones.js so pointer mapping works, gated on the destination existing.

**T243.3 — client CEF-operator mode** (`client/lib/cef-operator-mode.js`, new + minimal touches in preview-canvas-panel.js)
- Mode = `new URLSearchParams(location.search).has('cefOperator')`.
- When active: add class `cef-operator` to `<html>`; CSS (new file in the styles split convention, @import at the right cascade point): compose-preview cells + page/panel backgrounds behind them become `background: transparent`; the preview canvases are NOT drawn (skip scheduleDraw work, don't just hide — save the CPU).
- Rect reporting: on compose-cell layout changes (reuse the existing ResizeObserver + a window resize/scroll listener, debounced 200ms client-side), POST viewport-fraction rects of each visible compose cell to `/api/operator-gui/layout`. When the panel collapses/unmounts or cells hide → POST the reduced set (or DELETE when none).
- Everything is inert when the query param is absent — ZERO behavior change for normal browsers (hard requirement; the smoke must assert the mode gate).

**T243.4 — smoke tests** (`tools/smoke/smoke-wo243-operator-gui.test.js`, curated gate)
- Destination CRUD validation (single-instance rule, defaults).
- Generator: operator_gui channel + screen consumer emitted; NO emission when absent; not in programChannels.
- Layout endpoint pure logic: cells → expected AMCP line list (PLAY route/FILL/STOP hygiene) with a stubbed amcp recorder; router registration greps.
- CEF-mode gate: cef-operator-mode module returns inactive without the query param (jsdom-free — test the pure functions).
