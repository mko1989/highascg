# WO-846 — Work-order housekeeping: categorize, index, deprecate

**Status: IN PROGRESS (30.10) — investigation written; classification next**
**Area:** process
**Source:** owner 30.10: "make a work order to analyze all work orders, categorize them and do general house keeping with
them (make a deprecated category too). they are the backbone of this whole project, the idea is for them to be easily
searchable by ai so good organization minimizes token usage and allows for precision edits."

## 1. Investigation

Survey of `work/work-orders/` on 30.10:

- **866 files, 9.4 MB.** 803 are `NNN_WO_<slug>.md`. 62 are not: audits, logs, notes, plans and old unnumbered WOs.
  Examples are `audit_report.md`, `fixing1.md`, `halucinations.md`, `issues24.07.26`, `logs.19.07.26`,
  `HighAsCG.code-workspace`, `WO-07_…`, `WO_fix-ab-bank-…` and `PROJECT_TRIAGE_2026-07-03.md`.
- **Duplicate numbers:** 09, 121, 33, 44 and 79 each name two different WOs. For example, `121_WO_CI_ENFORCE_500_LINE_LIMIT`
  and `121_WO_USB_WEBCAM_V4L2_INPUT` share one number.
- **The status line has drifted.** Within the first 8 lines the status reads `DONE` in 359 files, `IN PROGRESS` in 52,
  `IMPLEMENTED` in 28, `FIXED` in 27, `DEPRECATED` in 20, `OPEN` in 17, and a free-form sentence in about 130 others
  ("ROOT CAUSE CONFIRMED + FIXED IN REPO…", "C…", "D…"). **27 files have no status line at all** in their header.
  Older WOs (≤ ~150) carry an "AGENT COLLABORATION PROTOCOL" preamble before any status.
- **No category exists anywhere.** To find the audio WOs, an agent must `rg` the whole 9.4 MB and read hits. Every
  session pays that cost again.
- **`work/OPEN_ISSUES.md` (654 lines, 478 rows) only partly mirrors the WO files.** Its status column disagrees with WO
  status lines in places. The WO line is the one CLAUDE.md says wins.
- **The deprecated material is split.** `work/deprecated/` holds old scripts and tools, not WOs. Only 20 WOs say
  DEPRECATED, yet many more describe removed subsystems: the kiosk (WO-646), the persistence partition, the HTTPS proxy,
  the 6 GiB stick offset, the Godot branch and the pre-26.04 Caspar build. Those still read as live truth to an agent.
- **55 references point into `work/work-orders/` from outside `work/`.** They are in code comments (`src/audio/meter-health.js`,
  `src/engine/scene-take-teardown-opacity-wait.js`, `src/tracking/register.js`…), smokes
  (`smoke-wo540-teardown-opacity-verify`), the curated CI list, `CLAUDE.md` and ~25 docs. WOs also link each other
  heavily, and `OPEN_ISSUES.md` links every row. **Renaming or moving a live WO breaks paths** unless every reference is
  rewritten in the same commit.

## 2. Design (decided by the coordinating session; owner can override)

The goal is the fewest tokens to find the right WO, plus exact paths for precision edits.

1. **One index file read first:** `work/work-orders/INDEX.md`, generated by a script and never hand-edited. It has one
   line per WO: `WO-NNN · STATUS · area · title · file`, grouped by area, with DEPRECATED rows in their own section at
   the end. It sits next to `index.json` (same data, for tools). An agent reads the INDEX (~60 KB) or `rg`s it instead of
   grepping 9.4 MB.
2. **Live WO paths stay flat and keep their names.** Categories are a header tag (`**Area:** <area>[, <area>]`), not
   folders. Folder moves would break the 55 outside references and the hundreds of WO-to-WO links for no gain the index
   does not already give.
3. **Deprecated is a physical category:** `work/work-orders/deprecated/NNN_WO_….md`. A plain `rg` of
   `work/work-orders/*.md` then skips dead approaches by default. Each move rewrites every reference to that file in the
   same commit (`tools/wo/move-wo.js`). A deprecated WO must name its reason and successor in the status line.
4. **Canonical header** (first lines after the title):
   `**Status: OPEN | IN PROGRESS | DONE (date, how verified) | DEPRECATED (reason; successor WO-NNN)**`, then
   `**Area:** …`. Synonyms are normalized: FIXED and IMPLEMENTED become `DONE (…original text…)`, free-form lines are
   mapped by reading the WO, and the original wording is kept inside the parentheses. Nothing is lost.
5. **Non-WO files leave the WO folder.** Notes, audits and plans go to `work/notes/`, logs to `work/archive/logs/`.
   Unnumbered old WOs (`WO-07_…`, `WO_fix-…`) get the next free numbers, or go to deprecated if dead.
6. **Duplicate numbers stay.** They are already cited in commits. The index lists both and disambiguates them by slug.
7. **Area taxonomy** (one primary, optional secondaries): `engine` (looks/takes/timeline/playback), `amcp`,
   `caspar-build`, `audio`, `video-io` (DeckLink/NDI/v4l2/vcam/record), `mapping` (pixel map, screens, multiview,
   destinations), `lighting` (DMX/Art-Net/sACN/fixtures/consoles), `godot-client`, `web-client`, `companion`,
   `devices-config`, `os-iso` (eggs/stick/kernel/nvidia/boot), `network` (cluster/replication/tailscale/auth),
   `media` (library/thumbnails/ingest/transcode), `tracking-vr`, `testing-ci`, `process` (docs/wiki/audits/WO tooling).
8. **Tooling with a guard:**
   - `tools/wo/build-index.js` regenerates the index.
   - `tools/wo/check-wos.js` validates every WO header (status vocabulary, area tag, deprecated → successor), checks the
     index is current, and checks no reference points at a missing WO file.
   - Both are wired into a curated smoke, so drift fails CI instead of accumulating.
   - CLAUDE.md "Before working on ANY issue" changes to: read or `rg` `work/work-orders/INDEX.md` first.
9. **`OPEN_ISSUES.md` reconciled.** Its status column is regenerated from the WO status lines. It stays the queue of
   non-DONE items, and its DONE rows move into the index.

## 3. Plan

- **A. Classification (read-only, Sonnet agents in parallel batches).** Each agent reads the header and skims each WO in
  its slice. It writes JSON rows `{file, wo, title, status, statusText, area[], deprecated?, reason, successor,
  confidence}` to the scratchpad. Deprecation needs evidence: the WO says so, a later WO supersedes it, or the subsystem
  is gone from the tree (cite `file:line` or the absence).
- **B. Review.** The coordinator spot-checks every deprecation and every low-confidence row against the code.
- **C. Apply mechanically** (a script, not hand edits): header normalization, area tags, deprecated moves with
  reference rewrite, and moving non-WO files out.
- **D. Tooling, index, check smoke, CLAUDE.md, OPEN_ISSUES reconcile.**
- **E. Verify.** The check passes, there are no dangling references (`rg` of every moved path), the curated suite stays
  green, and 3 sample "find the WO about X" queries are answered from INDEX.md alone.
