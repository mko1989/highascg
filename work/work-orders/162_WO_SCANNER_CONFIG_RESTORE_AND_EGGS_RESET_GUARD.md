## 1. Investigation findings (2026-07-13)

- **The file:** `/home/casparcg/highascg/scanner.config` — XML config for the CasparCG media-scanner. The scanner runs as `casparcg-scanner.service` (`scripts/systemd/casparcg-scanner.service`) with **`WorkingDirectory=/home/casparcg/highascg`**; the binary (Node SEA bundle of CasparCG/media-scanner, port 8000, watching `media/`) reads its config **relative to cwd** — hence the repo-root location, deliberately separate from `config/` (which holds the *server's* casparcg.config). Untracked in git (not gitignored, never committed at root), matching "machine-local, does not change."
- **Confirmed missing** at investigation time: `find /home/casparcg -iname scanner.config` → nothing; not restorable from git at that path (never tracked there). Canonical content recovered from history: `git show 5c746a2~1:examples/scanner.config` (template deleted in refactor `5c746a2`; also existed as `work/scanner.config` in `3797061`/`70619f3`).
- **Deletion vector:** no script references `scanner.config` by name; no `git clean`/root `rsync --delete` in the eggs flow. The only produce-path code that deletes non-versioned root files is the **factory reset**: `tools/eggs/live-usb/build-highascg-egg.sh:89` → `reset-iso-operator-config.sh` (:48 removes root `.env`; :22-27 runs the reset writer) → **`write-iso-default-config.js:75-83`** — deletes all `config/*.json` outside a `PRESERVE_JSON` whitelist and `unlinkIfExists` on root-level runtime files (`highascg.config.json`, `.highascg-state.json`, `.module-state.json`, `autosave.json`). `scanner.config` is not in any preserve list, so the produce factory-reset is the mechanism of record (documented in `EGGS_PRODUCE_SAFETY.md:26-28`).
- **Root cause making it sticky:** `scripts/setup/08-caspar-cef-scanner.sh` installs the scanner deb but **never lays down `scanner.config`** (it only seeds `config/casparcg.config`, :71-75) — once deleted, nothing ever recreates it.
