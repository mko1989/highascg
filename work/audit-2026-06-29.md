# HighAsCG Codebase Audit (2026-06-29)

**Objective:** Audit the codebase (server and client) to evaluate code connections, import/export patterns, function structures, and general adherence to Node.js / ES best practices.

## 1. Architectural Patterns & Connections

### Server-Side (`src/`)
- **Module System:** Uses CommonJS (`require` / `module.exports`).
- **Entry Point (`index.js`):** The orchestrator is well-structured. It initializes subsystems (Config, State, HTTP, WebSocket, Caspar AMCP, OSC, Streaming) sequentially and injects an `appCtx` (Application Context) into them. This is a very good practice (Dependency Injection) that avoids tight coupling and hidden global states.
- **Optional Modules (`src/module-registry.js`):** Implements an excellent registry pattern for optional features (`previs`, `tracking`, `autofollow`, `cg-studio`). Core code never directly imports from these directories. They are loaded dynamically, and if missing, the app continues to boot.
- **Routing (`src/api/router.js`):** The router correctly splits HTTP handlers into domain-specific files (`routes-media.js`, `routes-scene.js`, etc.). However, the main dispatch mechanism in `router.js` is a very long sequence of `if (method === 'GET' && p === '...')` blocks. 
  - *Recommendation:* Consider adopting a lightweight routing tree (like an Express-style router or Radix tree) to reduce the cyclomatic complexity of `router.js` (currently 543 lines).

### Client-Side (`client/`)
- **Module System:** Uses modern ES Modules (`import`/`export`).
- **Structure:** Separated cleanly into `components/` (UI rendering and logic) and `lib/` (state, API, and utilities).
- **State Management:** Uses a custom `StateStore` and individual state modules (`sceneState`, `multiviewState`, `settingsState`), which subscribe to WebSocket events and update the UI. This is a solid, decoupled reactive pattern.
- **Imports:** Imports are clean, relative, and explicit (including the `.js` extension, which is correct for native browser ESM).

## 2. Dependency Management & Imports

### Lazy Loading / Inline Requires
In files like `index.js` and `periodic-sync.js`, I found several inline requires (e.g., `require('./src/system/pointer-confine')` inside a function body). 
- **Pros:** This successfully breaks circular dependencies and defers execution until the feature is actually invoked.
- **Cons:** It can make tracking dependencies harder for static analysis tools (and our upcoming WO-83 Map tool).
- **Assessment:** Acceptable for a monolithic app of this scale, especially to speed up the critical boot path or avoid cyclic module resolution.

### Missing `'use strict'`
The vast majority of the `src/` directory correctly declares `'use strict'`. A quick scan found a few files missing it:
- `src/plugins/plugin-manager.js`
- `src/cg-studio/http-utils.js`
- `src/cg-studio/template-scan.js`
- `src/cg-studio/routes.js`
- `src/system/exfat-sync-fs.js`
*Recommendation:* Add `'use strict'` to the top of these files to enforce modern JS parsing rules globally.

## 3. Function & File Structure

### File Sizes
The project does a great job keeping files small and focused. Out of ~350 server files, only ~10 are slightly over 500 lines. The largest files are:
1. `routes-scene.js` (574 lines)
2. `build-caspar-generator-config.js` (571 lines)
3. `alsa-mixer.js` (559 lines)
4. `decklink-output-resolve.js` (554 lines)
5. `router.js` (543 lines)

*Assessment:* These sizes are well within acceptable bounds for a Node.js backend. None of them are unwieldy monolithic "God files".

### Global / Mutable State
There are a few instances of module-level mutable state (`let`) used for timers and caching, such as in `src/utils/periodic-sync.js`:
```js
let oscChannelsBlobTimer = null;
let oscChannelsBlobCtx = null;
```
*Assessment:* Because Node.js caches modules, these act as singletons. This is standard practice for debouncing/throttling across the application, provided they are cleaned up on shutdown (which they appear to be).

### Error Handling
- The boot sequence in `index.js` contains excellent error boundaries. If the main configuration fails to load or Caspar cannot connect, it catches the error and boots a "Safe Mode" HTTP UI so the operator can fix the configuration via the browser.
- API endpoints return consistent JSON error objects (`{ error: '...' }`) with appropriate 50x HTTP status codes.

## 4. Summary & Best Practices Verdict

**Verdict:** The HighAsCG codebase is exceptionally healthy and adheres to high-quality Node.js best practices.

**Strengths:**
1. **Dependency Injection:** The `appCtx` pattern prevents spaghetti connections between AMCP, HTTP, and WebSocket layers.
2. **Resilience:** Safe mode fallback on boot, file-locked singleton launches (`run.sh`), and asynchronous AMCP reconnection logic show a deep understanding of production reliability.
3. **Client/Server Split:** Serving a native ESM client directly from a custom HTTP server without a heavy build step during runtime keeps the system lean and predictable.

**Areas for Minor Improvement:**
1. Refactoring the giant `if/else` chain in `src/api/router.js` into a routing map/registry.
2. Adding `'use strict'` to the ~10 files missing it in the `cg-studio` and `plugins` directories.
