### Key findings (short)

- Vanilla ESM, no framework. DOM is built from `innerHTML` template strings plus `addEventListener`. Singletons are module-level objects (`stateStore`, `settingsState`, `projectState`, `sceneState`). Cross-component events are `CustomEvent`s on `window`/`document`.
- The WebSocket is the only push channel. Envelope is `{type, data}`. The client dispatches on `type` and hands handlers only `data`.
- Dead or unwired code in scope: `components/sync-modal.js` and `components/publish-modal.js` have zero importers. `assets/modules/cg-studio/entry.js` is referenced by neither the server `webBundles` nor the client registry. `WsClient.sendAmcp` / `sendAmcpStructured` have no in-app callers. `apiPut` has no in-scope callers.
- Port-risk defects observed in code:
  - `lib/deferred-catalog-ws.js:58,100` double-encodes WS frames (`JSON.stringify` then `WsClient.send` stringifies again). The server drops frames that do not start with `{` or `[` (`src/server/ws-server.js:316-317`). Result: the WS catalog path always times out after 120 s and falls back to `GET /api/state`.
  - `window.showToast` is read in `components/header-bar.js:221,224` but never assigned anywhere in `client/`. Those error toasts are silent no-ops.
  - `StateStore._emit` invokes `'*'` listeners twice when `setState` is used (`lib/state-store.js:86-91`).
- The settings modal has no Save button. Every field change schedules a 600 ms debounced `POST /api/settings` with the whole settings object (`components/settings-modal.js:249`, `components/settings-modal-logic.js:68-144`).

## 2. WebSocket client

### 2a. `WsClient` (`lib/ws-client.js`, 206 LOC)

- URL: `getWsUrl()` (`lib/api-origin.js:170-180`) = `ws(s)://<origin>[<companion prefix>]/api/ws`. Server upgrades `/api/ws`, `/ws` and `/instance/<id>/api/ws` on the HTTP port (`src/server/ws-server.js:2, 230-231`).
- Options (`ws-client.js:28-32`): `reconnectInterval` 1000, `maxReconnectInterval` 30000, `maxReconnectAttempts` Infinity, `amcpTimeoutMs` 10000.
- Constructor calls `_connect()` (`:38`).

Inbound envelope (server side: `src/server/ws-server.js:136` `safeStringify({type: event, data})`):

```
{"type": "<string>", "data": <any>}
```

Client parse (`ws-client.js:127-147`):
- Accepts string, `Blob` (`text()`), or `ArrayBuffer` (`TextDecoder`). Anything else is ignored.
- Trims. Drops frames whose first char is not `{` or `[` (`:136`).
- `JSON.parse`. Emits `'message'` with the full envelope (`:138`).
- If `msg.type` is set: `'error'` is re-emitted as `'server_error'` (`:141`) to avoid colliding with the transport error event; any other type is emitted as `emit(msg.type, msg.data)` (`:142`).
- Parse errors are `console.warn`ed (`:145`).

Transport events:
- `connect`: `onopen` (`:122-125`) resets `reconnectAttempts = 0`, emits `connect`.
- `disconnect`: `onclose` (`:149-152`) emits `disconnect`, then `_reconnect()`.
- `error`: `onerror` (`:154`). Also emitted when `new WebSocket` throws (`:116-118`).

Reconnect (`:16-24`, `:157-170`):
- `computeWsReconnectDelay(n) = min(30000, 1000 * 2^min(n-1, 5)) + floor(random * min(1000, exp*0.2))`.
- Sequence before jitter: 1 s, 2 s, 4 s, 8 s, 16 s, 30 s, 30 s, …
- Unlimited attempts (`maxReconnectAttempts = Infinity`).
- `close()` (`:172-182`) sets `_stopped`, so no reconnect. `reconnectNow()` (`:185-201`) forces a new socket.

Outbound:
- `send(obj)` → `JSON.stringify(obj)` and `ws.send`, only when `readyState === OPEN`. Otherwise silently dropped; no queue (`:58-66`).
- `sendAmcp(cmd)` (`:96-100`) sends `{type:'amcp', cmd, id}`. `sendAmcpStructured(payload)` (`:107-111`) sends `{...payload, id}`. Both return a Promise resolved by a later `amcp_result` with the same `id`, with a 10 s timeout (`_waitAmcpResult`, `:68-94`). **No in-app callers.**
- `on(event, fn)` returns an unsubscribe function (`:41-51`). `emit` calls listeners in registration order (`:53-56`).
- `get connected()` = `readyState === OPEN` (`:203-205`).

### 2d. Port-risk notes (WS)

- Frame double-encoding: `deferred-catalog-ws.js` passes a JSON string to `ws.send`, which stringifies it again. The server sees a frame starting with `"` and drops it. The client waits 120 s (`:33-36`) then falls back to HTTP (`:103-106`).
- `WsClient.send` silently drops when not OPEN. Anything sent during a reconnect window is lost.
- `state` is a full snapshot on every connect and on the catalog path, so a Godot client must treat it as authoritative.
- `change` has a seq-gap rule for `scene.live` (`app-ws-handlers.js:142-148`): a gap triggers `GET /api/state` (`refreshSceneLiveFromServer`).
- Server closes slow clients at a buffer threshold (`src/server/ws-server.js` `terminated slow client`), so clients must keep up.

## 3. State store and settings state

### 3a. `StateStore` (`lib/state-store.js`, 121 LOC)

- Holds `_state` (plain object), `_listeners` (Map key → fn[]) and `_isOffline` (`:9-14`).
- Keys are dotted paths. `_set(path, value)` (`:56-74`) creates intermediate objects, then `_emit(path, value)`. For the four cached keys (`media`, `templates`, `channelMap`, `mediaProbe`) it also writes an IndexedDB snapshot when not offline (`:68-73`).
- `setState(full)` (`:93-110`): replaces `_state` with a shallow copy of `full`. `structuredClone` is applied to `channelMap`, `scene`, `variables`. Emits `'*'`. Writes IndexedDB snapshots for `media`, `templates`, `channelMap` (not `mediaProbe`). If `full` is not an object, `_state` becomes `{}`.
- `applyChange(path, value)` (`:112-114`) = `_set`.
- `getState()` (`:116-118`) returns the live object (no copy). Mutating it bypasses listeners.
- `on(pathOrKey, fn)` (`:43-54`) returns an unsubscribe function. No batching or coalescing.
- `setOffline(bool)` (`:16-19`) emits `'offline'`. `isOffline()` (`:21-23`).
- `hydrateFromCache()` (`:25-41`) loads `media`, `templates`, `channelMap`, `mediaProbe` from IndexedDB into `_state`.

Emit semantics (`:86-91`): `_emit(path, value)` calls listeners on `path` with `(value)` and then calls listeners on `'*'` with `(path, value)`. For `_set` this means `'*'` fires once. For `setState`, `path` is `'*'`, so the `'*'` list runs twice per call. Port should match or deliberately fix this.

Keys read or written by in-scope code (not exhaustive): `media`, `templates`, `channelMap`, `mediaProbe`, `variables`, `timeline.tick`, `timeline.playback`, `scene.live`, `scene.deck`, `scene.globalBorders`, `caspar.connection`, `caspar.*`, `configComparison`, `extraLiveSources` (`app.js:317`), `hostOperatorFullscreen` (`app.js:320`), `catalogDeferred`, `osc.channels` (via `state`). ### 4c. Port-risk notes (API)

- Base URL precedence is implicit in browser context (`location`, meta tags, `import.meta.env`). A Godot client needs an explicit base URL setting and must reproduce the same-origin/override semantics where they matter (A/B failover, §15).
- Every failure is surfaced as a string message (`HTTP 409: …`). Callers branch on `err.status`, `err.reason`, `err.storedRev`, so the error shape must carry those fields.
